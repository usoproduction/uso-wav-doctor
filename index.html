How to use it

  1. Keep the damaged file safe. Work on a copy if you can, and don't record over the drive or card it came from.
  2. Drop the file on the box above (or click it to browse). You can add several files at once.
  3. Read the report. OK means the header is already fine. Header needs fixing means the tool can repair it automatically. Needs manual input means the format information is lost and you'll have to tell the tool how the file was recorded (see below).
  4. Press ▶ Preview to listen to the result right on the page, then ⬇ Repair & download. You'll get a new file called yourfile_repaired.wav in your downloads folder.
  5. Open the repaired file in your DAW or editor and listen all the way through, especially the last seconds, where the crash happened. A short glitch at the very end is normal and can simply be trimmed.

What it can and can't fix

Can fix

  • Recordings interrupted by an app crash, a frozen computer, a power cut, a full disk or an unplugged drive
  • Files that show 0:00 duration, won't open, or play silence although the file size is large
  • Wrong or missing size values in the header
  • A completely missing header, as long as the raw audio is still in the file (manual mode)

Can't fix

  • Audio that was never written to disk — if the file is 0 KB or tiny, the audio isn't in it
  • Files damaged by a corrupted card or drive (use a file-recovery tool first, then come back)
  • Dropouts, clicks or gaps inside the recording itself
  • Compressed formats: MP3, AAC, FLAC, OGG, ALAC…
  • Files over 4 GB (RF64/W64 output is not supported)

Intact metadata chunks such as BWF bext, iXML, markers (cue) and LIST info are kept in the repaired copy. Damaged ones are dropped.

Manual mode: finding the right settings

If the tool can't find the format information, it asks you for it. Start from what your recorder or session was set to — 48000 Hz / 24-bit / stereo / PCM is the most common combination, and it's the default. Press ▶ Preview after each change and listen:

What you hearWhat to change
Loud harsh noise or heavy distortion, but you can sense the rhythm of the recording underneathBit depth (try 16, 24, 32) or format (PCM vs float). 32-bit recordings are usually float.
Pure white noise with no structure at allFormat first (PCM / float), then bit depth. If nothing works, the data may not be audio.
Sounds right but too high and fast, or too low and slowSample rate (e.g. 44100 vs 48000, or 48000 vs 96000).
Roughly half or double speed with a grainy, gritty edgeNumber of channels (mono vs stereo, or a multichannel count).
Correct sound but left and right swapped, or a strong click at the very startData offset. Leave the suggested value or try 44; it should be a multiple of the bytes per frame.

FAQ

Is my audio uploaded or stored anywhere?

No. The file is read and rebuilt by your browser on your own computer. Nothing is sent over the network, there are no cookies and no analytics. You can save this page and use it offline.

Will it change my original file?

Never. The browser has no way to write back to it: the tool only creates a new _repaired.wav copy.

Why did my file break in the first place?

A WAV file starts with a short header that says how long the audio is. Most recording apps write a placeholder there and fill in the real values only when you press stop. If the app crashes first, the audio is on disk but the header still says "0 bytes", so players think the file is empty. This tool measures the real length and rewrites the header.

How large can files be?

The whole file is loaded into memory, so the limit depends on your browser and computer. Files up to about 1–2 GB work in current desktop browsers; WAV files can't exceed 4 GB anyway.

Which browsers are supported?

So far it has been tested on desktop Google Chrome. Other modern browsers (Edge, Firefox, Safari) should work, but haven't been tested yet — if something goes wrong, try Chrome.

What does the coloured bar on each file mean?

It's a map of the file's internal structure: grey is the header, amber the format chunk, purple metadata, green the audio and red a region that couldn't be read. A healthy file is mostly green.

The repaired file still doesn't sound right. What now?

Try manual mode with different settings (button "Force manual parameters"). If the audio itself was damaged, a header repair can't help and a specialised audio-restoration tool is the next step.
